# Risk management (ISO 14971 starter)

This file is a starter hazard analysis for in-repo 510(k) readiness. It is not a complete ISO 14971 risk-management file and does not replace a manufacturer QMS.

Software safety classification for planning: IEC 62304 Class C (incorrect antibody identification can contribute to incompatible transfusion).

| ID | Hazard | Foreseeable sequence | Harm | Control | Verification |
|---|---|---|---|---|---|
| R-01 | Wrong antibody identification | Engine mis-scores reactions or user accepts suggestion without review | Incompatible transfusion | Professional confirmation required; lock after confirm; analysis snapshot | `Fda510kControlTests`, analysis golden tests |
| R-02 | Missed clinically significant antibody | Threshold / ACS settings too permissive | Delayed or missed ID | Settings clamp; ACS tests; settings change audit | `AcsEvaluationTests`, settings audit |
| R-03 | Seed / demo data treated as patient work | Empty production DB auto-seeded; demo data loaded into a laboratory database (look-alike accessions, active look-alike lots) or left half-loaded | Wrong patient result | No auto-seed on launch; explicit Tools > Load Demo Data or `--seed-clinical`, refused unless the database is empty or demo-only, loaded in one transaction (`DemoDataGuard`) | `Fda510kControlTests.FreshDatabase_HasNoSeededSpecimens`, `DemoDataGuardTests` |
| R-04 | Post-confirmation edit | Reactions changed after final call | Result no longer matches signed ID | Record lock; clear requires reason + audit | `Fda510kControlTests.ConfirmedSpecimen_LocksReactionsAndAnalysisWrites` |
| R-05 | Settings drift | Probability / ID rule / ACS count changed silently | Different engine output | Clinical settings snapshot on analysis; settings audit | Snapshot + `update_settings` audit |
| R-06 | Untraceable calculation | Cannot reconstruct why a result was produced | Unable to investigate incidents | Snapshot: version, settings, input fingerprint, ACS/rule-out/suspect JSON | `Fda510kControlTests.AnalyzeSpecimen_PersistsTraceabilitySnapshot` |
| R-07 | Unlabeled software | User cannot see version or intended use | Misuse / untraceable reports | About, first-run, F1, report preamble | `Fda510kControlTests.Reports_IncludeIntendedUseVersionAndTraceLine` |
| R-08 | Lost forensic trail, or PHI in the log | Exception or data change with no record; log lines dropped when the file is held open; record identifiers written to the plain-text log | Unable to reconstruct event; disclosure | File log with shared, serialized writes; HemoIQ exception messages (accessions, MRNs) withheld and replaced by type and throwing method; no reaction grades; append-only `audit_events` | `AppLogPrivacyTests`, `Fda510kControlTests.AppLog_WritesVersionedLineWithoutThrowing`, audit tests |
| R-09 | World-readable PHI file | Weak NTFS ACL on database | Unauthorized disclosure | Local file + ACL tests | `HipaaSecurityTests` |
| R-10 | Vendor download to unexpected host | SSRF / unexpected network | Data leakage | HTTPS + URL allow-list | `HipaaSecurityTests` vendor URL tests |
| R-11 | Expired reagent or specimen used | Results recorded on a lot or specimen past its expiration date (an expired lot reactivated, or a specimen that expired while the application was open) | Interpretation from unreliable red cells or a specimen that no longer represents the patient | Save asks first; expired-lot activation warns on every route and is audited; analysis REVIEW note, report line and Worklist item for runs recorded after expiry | `ExpiredReagentTests`, `ExpiredSpecimenEntryTests`, `PanelEditAuditTests` |
| R-12 | Another patient's evidence in an identification | An eluate linked to a different patient's serum, or an MRN change that separates a linked pair | Wrong antibody identification | Eluate link and MRN changes refused when the MRNs differ; cross-specimen history keyed by MRN | `EluateEvidenceTests` |
| R-13 | Unreviewed antigram in use | Imported, copied or edited lot switched active without review of its antigram | Wrong rule-outs from wrong typing | Imported and copied lots stored inactive; every activation route shows the review prompt; panel detail edits record old and new values | `PanelEditAuditTests`, `LabCsvImportTests` |
| R-14 | Unobserved results recorded | Grades copied from one run into a treated run and saved as its results | False treatment evidence | Copy offered only for an untreated repeat, as unsaved values; treatment text built from the engine tables | `RunTreatmentTextTests` |
| R-15 | Missing typing read as negative | A truncated lot file whose missing columns are read as antigen-negative | Wrong rule-outs | Short rows refuse the whole file; malformed structured files are refused with a reason | `LabCsvImportTests`, `StructuredImportParserTests` |
| R-16 | Accidental deletion | Enter pressed through a purge or delete confirmation | Loss of records | Every deleting confirmation defaults to No; Purge is not the Enter button | `DestructiveConfirmTests` |
| R-17 | Work recorded on an unwritable database | A read-only or held database file accepted at start-up, so saves fail only later | Results the user believes were recorded are lost | Read-only database refused at open with a plain explanation; application closes; failed saves roll back and keep the unsaved grades | `StartupFailureTests` |
| R-18 | Score read as a probability | Combined score printed as a bare percentage or described as a probability | Over-confidence in a suggested identification | Scores labelled as scores on screen, in the Summary and on reports; ACS exception worded as a combined score | `AcsEvaluationTests` |

Residual risk: professional confirmation is the primary clinical control. Residual submission items (predicate, QMS, clinical study) are listed in [gap-register.md](gap-register.md).
